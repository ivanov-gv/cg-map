# System architecture

This folder describes the implemented system, ownership boundaries, known architectural gaps, and historical system
design exploration. It is about how the software and data pipeline fit together, not visual or interaction design.

- [Current architecture](architecture.md) is the authoritative description of implemented behavior and boundaries.
- [Ownership](ownership.md) records component responsibilities and split triggers.
- [Technical debt](technical-debt.md) tracks known limits and deferred engineering work.
- [Historical implementation guide](historical-implementation-guide.md) is background only; current docs take
  precedence.
