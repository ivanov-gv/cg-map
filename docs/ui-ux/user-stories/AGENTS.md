# User stories and journey requirements

- Describe user intent, observable success, constraints, and target acceptance; do not present targets as implemented.
- Treat `user-stories.md` as the canonical source of maintained `US-##` IDs.
- Preserve IDs when wording or requirements evolve; connect user-visible features to relevant stories in `../features/`.
- Keep source-level implementation facts in the owning component and link to them instead of duplicating them.
