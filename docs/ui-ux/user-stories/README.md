# User stories and journey requirements

This folder owns the **why**: user outcomes to preserve and target requirements for the journey **Discover → Understand
→ Plan → Travel**.

- [User stories](user-stories.md) is the baseline of maintained capabilities, IDs, observable success, and boundaries.
- [Discover](discover.md), [Understand](understand.md), [Plan](plan.md), and [Travel](travel.md) expand the journey into
  target requirements and acceptance scenarios. Each states its implementation status; target requirements are not
  claims that the current product meets them.
- The [feature index](../features/README.md) links those user outcomes to the behavior that serves them.

Keep story IDs stable when refining a need. Add or change a story only when the user outcome or product promise changes;
do not create a story merely to justify an existing code detail.
