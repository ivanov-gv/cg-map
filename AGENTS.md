# Working on cg-map

Read [ARCHITECTURE.md](ARCHITECTURE.md) for the current stack and boundaries, then the relevant [docs index](docs/README.md). This is a read-only map/directory PoC, not an editorial backend or routing engine.

## Commands

- Setup: `make setup` (Node 24, Python 3.12; no Python packages needed to serve/test).
- Run: `make dev`; override `PORT` for parallel worktrees.
- Validate: `make check` (lint, data/provenance, docs/boundaries, Node/Python tests, Pages parity).
- After runtime/data changes: `make pages`, then `make check`.
- Browser: `npx playwright install chromium` once, then `make test-e2e`.
- Full geometry rebuild: `make build`; install [optional Python build dependencies](docs/runbooks/data.md) first. Do not rebuild geography for CSS/JS-only changes.
- Optional Go host: `make check-go` (Go 1.22+); CI checks it separately.

## Sources and generated files

- Edit application code/assets in `web/`; follow [web/AGENTS.md](web/AGENTS.md).
- Edit geometry in `source-data/`; follow [source-data/AGENTS.md](source-data/AGENTS.md).
- Root app files, `data/`, `fonts/`, `vendor/`, `.pages-manifest.json`, and `.nojekyll` are generated Pages output. Never patch them directly.
- `web/data/manifest.json` and `web/offline-manifest.js` are generated by `tools/finalize.mjs`.
- `docs/` contains documentation only. The publisher must never clear or overwrite it.
- Vendored libraries/notices and binary datasets are not ordinary code-edit targets. Dependency upgrades must update the browser bundles too.

## Workflow

1. Inspect git status, the task requirements, relevant code, and tests. Preserve unrelated work.
2. Define observable acceptance criteria. For multi-session work, record decisions, completed steps, and remaining work in `docs/plans/`; use its template.
3. Make a bounded change. Enforce rules in checks where practical; avoid speculative infrastructure.
4. Run relevant checks and then `make check`. For UI/offline changes run browser tests; report unavailable checks explicitly.
5. Review the diff, generated output, and docs together. Do not weaken tests or provenance checks to obtain a green result.
6. Report behavior changes, verification evidence, and remaining limitations. Never claim browser/device performance from unit tests.

## Invariants

- No third-party runtime network dependency: libraries, glyphs, places, and the satellite sample are local.
- PMTiles range requests must remain separate from the service-worker shell cache.
- Preserve verified offline downloads until a replacement succeeds.
- Pure modules must not depend on DOM orchestration or build tools; `tools/check-repo.mjs` enforces the current graph.
- Preserve data attribution and source history. Current basemap extracts lack stable upstream IDs; do not invent identity guarantees.
- Use isolated worktrees/ports for simultaneous tasks. Keep credentials and production state outside the repository and test environment.
